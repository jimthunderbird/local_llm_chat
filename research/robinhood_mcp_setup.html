/robinhood: why it returns "Unknown server error" and what to configure

Research only. Inspected app/chat_server.py, app/chat.html, prompts/robinhood.prompt, .chat/, the running chat_server.py process environment, and the upstream robinhood-mcp package (PyPI 0.1.2).

Short answer: yes, /robinhood needs configuration, and nothing is configured right now. There is no .chat/robinhood_mcp.json, no ROBINHOOD_MCP_* environment variable, and no token file, so the command cannot reach any MCP server. The browser shows Unknown server error. only because a second, independent bug discards the real "Robinhood MCP is not configured" message.

1. What is actually missing

/robinhood <symbol> is registered in the command list (app/chat_server.py:354) and dispatched at app/chat_server.py:21544-21545. It calls robinhood_holdings_report() (:3058), which builds an MCP client from _robinhood_mcp_config() (:2208). The client refuses to start when it has neither a command nor a token (:2330) and raises the setup help from _robinhood_mcp_setup_help() (:2272).

Environment variables are read from the process that runs chat_server.py, so exporting them in a different terminal has no effect on an already-running server. Restart it after changing them.

2. Why the UI says "Unknown server error"

This is a presentation bug in the command's error path, not the underlying failure. The server emits two different payload shapes for the SSE error event:

Emitter Payload Result in browser
Most error paths, e.g. app/chat_server.py:20118, :21677 {"message": "..."} Message displayed correctly
_command_robinhood at app/chat_server.py:24580 {"text": "..."} (via _sse_text at :18743) data.message is undefined, so the fallback string is shown

The browser handler reads only message: 

// app/chat.html:18091 (handlers for streamSSE("/api/ask", ...) at :18100)
error: (data) => addError(entry, data.message || "Unknown server error."),

streamSSE() parses the SSE payload faithfully (app/chat.html:17428), so the {text: ...} object arrives intact and is simply ignored. The actionable setup instructions never reach the screen.

The same mistake exists in other commands. /mdn (:23806), /britanica (:23880), /stackoverflow (:23959), /wikivoyage (:24040), /map (:24207), and /article (:25194) also call _sse_text("error", ...). Their real errors are masked the same way.

A minimal fix (not applied — this document is research only):

# app/chat_server.py:24580
-            self._sse_text("error", f"\n/robinhood: {exc}\n")
+            self._sse("error", {"message": f"\n/robinhood: {exc}\n"})

3. What to configure

3.1 Local stdio server (recommended)

The community package robinhood-mcp (v0.1.2, Python ≥ 3.11) is a read-only MCP server built on robin_stocks. It uses the stdio transport that the client already implements (_start_stdio, app/chat_server.py:2377).

Create .chat/robinhood_mcp.json (the whole .chat/ directory is gitignored, so credentials stay out of git):

{
  "command": "uvx robinhood-mcp",
  "env": {
    "ROBINHOOD_USERNAME": "you@example.com",
    "ROBINHOOD_PASSWORD": "your-password",
    "ROBINHOOD_TOTP_SECRET": "optional-base32-secret"
  }
}

Or use environment variables instead of the JSON file:

export ROBINHOOD_MCP_COMMAND='uvx robinhood-mcp'
export ROBINHOOD_USERNAME='you@example.com'
export ROBINHOOD_PASSWORD='...'
export ROBINHOOD_TOTP_SECRET='...'   # only if using an authenticator app
make start
Variable Required Purpose
ROBINHOOD_USERNAME Yes Robinhood login e-mail
ROBINHOOD_PASSWORD Yes Robinhood password
ROBINHOOD_TOTP_SECRET Only with an authenticator app Base32 TOTP secret (A–Z, 2–7). Omit for SMS / push / passkey accounts.
ROBINHOOD_APPROVAL_TIMEOUT No Seconds to wait for a push approval; default 60

First use performs the login, which takes roughly 5–10 seconds. Without a TOTP secret, the first call triggers a push notification in the Robinhood mobile app; approve it within the timeout window. The session is then cached in ~/.tokens/robinhood.pickle and reused until it expires.

The client also accepts the server through {"command": ["uvx", "robinhood-mcp"], "args": [...]} and merges the JSON env block into a copy of the server's environment (_robinhood_mcp_config, app/chat_server.py:2208-2270).

3.2 Official HTTP endpoint (limited support)

Do not expect the official endpoint to work unattended. https://agent.robinhood.com/mcp/trading uses OAuth 2.1 authorization-code + PKCE as a public client. The client here only sends a static Authorization: Bearer <token> (app/chat_server.py:2475-2481) and has no OAuth flow, refresh, or dynamic client registration. A pasted token will expire with no renewal path.

The official route also requires a funded Robinhood Agentic account and grants read access to all Robinhood accounts. If you still want to try it, put a fresh token in the environment or a token file: 

export ROBINHOOD_MCP_URL='https://agent.robinhood.com/mcp/trading'
export ROBINHOOD_MCP_TOKEN='<OAuth access token>'

A 401 from this endpoint is expected and healthy for an unauthenticated probe — it confirms the endpoint is up and protected: 

curl -s -D - -o /dev/null -X POST https://agent.robinhood.com/mcp/trading \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"probe","version":"1.0"}}}'

3.3 Precedence

Per _robinhood_mcp_config(): environment variables override .chat/robinhood_mcp.json, which overrides the default URL; a token value overrides the standard token files. Setting ROBINHOOD_MCP_COMMAND in the environment also makes the JSON args array be ignored.

4. How to verify

  1. Add the config (JSON or environment variables).
  2. Restart chat_server.py (make start), because the process only sees environment variables set before it launched.
  3. Run /robinhood AAPL in the browser.
  4. If it still fails, test the MCP server independently of the chat server:
printf '%s\n' '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"probe","version":"1.0"}}}' \
  | ROBINHOOD_USERNAME=... ROBINHOOD_PASSWORD=... uvx robinhood-mcp

The server should print an initialize result on stdout; diagnostics and login errors go to stderr. Until the SSE payload bug is fixed, those details are not visible in the browser — they would only appear as Unknown server error.

5. Notes and caveats

  • Credentials are local. The local server authenticates directly with Robinhood; no credentials are sent to this chat server. The session pickle lives in ~/.tokens/robinhood.pickle.
  • Read-only. robinhood-mcp exposes no trading tools. The official MCP endpoint, by contrast, can place trades in a dedicated Agentic account.
  • Unofficial API. The local server wraps robin_stocks; Robinhood can change or rate-limit it at any time (HTTP 429s are common under heavy use).
  • Multiple accounts. Account-scoped tools may require an account number; the command discovers one through robinhood_get_accounts when a tool schema requires account_number (app/chat_server.py:3080-3093).
  • Tool naming is tolerant. The report matches many naming conventions — get_position, robinhood_get_position, get_stock_positions, get_open_orders, get_order_history, and related names (app/chat_server.py:2174-2206).
  • Network access. The first uvx robinhood-mcp run downloads the package and its dependencies; allow for that on the first call.
