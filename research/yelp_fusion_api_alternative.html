Free, no-API-key alternatives to Yelp Fusion v3

Research for the /map → Nearby Restaurants feature: given a restaurant's latitude and longitude, retrieve its style of food, address, and opening hours without a Yelp key or per-call charges. Researched 2026-11-13.

Recommendation: use the OpenStreetMap Overpass API as the primary source (it is already what the /map list uses), add a small cache, and parse opening_hours with a real parser. For broader name/category/address coverage, optionally index Overture Maps Places or Foursquare OS Places locally. If an API key is acceptable, Geoapify (3,000 credits/day free) is the closest drop-in hosted alternative. Keep Yelp only if Yelp ratings/reviews or Yelp-branded content are a hard requirement.

1. Requirements and evaluation criteria

The feature needs a detail lookup keyed by coordinates (or by the OSM object already present in the /map result), returning as much of the following as possible:

  • Name and restaurant/café/fast-food type.
  • Style of food (cuisine), ideally normalized.
  • Address (street, number, city, postcode).
  • Opening hours, preferably machine-readable and summarizable ("open now", "closes at 22:00").
  • Bonus: phone, website, price level, dietary/accessibility tags, outdoor seating, delivery/takeaway.
  • Free and no API key for the primary path; no mandatory billing account.
  • Usable from a local Python server with a normal HTTP client and a reasonable response time.

Criteria used in the matrix: cost, key requirement, coordinate lookup, cuisine, address, hours, coverage, freshness, operational risk, and licensing/caching constraints.

3. OpenStreetMap Overpass API (recommended)

Overpass is a read-only query engine over OpenStreetMap. It needs no key, supports a radius search around a coordinate, and returns the raw OSM tags that contain exactly the fields we need. The existing /map restaurant tab already obtains its list this way.

Query by coordinate

[out:json][timeout:20];
(
  nwr["amenity"~"^(restaurant|fast_food|cafe|food_court)$"]
    (around:1200,37.7955487,-122.3934746);
);
out center 60;

Each returned element has type (node, way, or relation), id, a coordinate (or center for ways), and a tags object.

Query one exact restaurant

The list already knows the OSM object identity, so the detail lookup can fetch that exact object instead of re-searching by name and risking a mismatch:

[out:json][timeout:15];
node(365489125);
out center;

Use way(...) or relation(...) for the other OSM types. This is cheaper and more accurate than a second around query.

Coverage and quality

OSM is community-maintained, so completeness varies by city. A real Berlin restaurant extract (August 2026) illustrates the pattern:

FieldFilledShare of 4,760 restaurants
name4,73299.4%
addr:street3,86981.3%
cuisine3,78779.6%
opening_hours3,67977.3%
website1,80738.0%
phone1,59433.5%

Berlin is one of the best-mapped cities; smaller or less-edited areas will have lower coverage. Identity and location are near-complete, food category and hours are usually present, and contact details are the weak spot. OSM has no ratings, reviews, or popularity signals.

Strengths

  • Free, no key, no billing account, no per-call charge.
  • Direct lat/lon radius query and exact OSM-object lookup.
  • Returns cuisine, address, opening hours, phone, website, dietary and accessibility tags in one request.
  • ODbL data can be stored, transformed, and used commercially with attribution; a derivative database may need to remain ODbL.

Weaknesses

  • No ratings, reviews, photos, or popularity.
  • Coverage and freshness vary; some restaurants are missing or stale.
  • Public servers are volunteer-run and can be slow, return 429/504, or change policy. Commercial apps are expected to self-host or pay a provider.
  • opening_hours is a rich, non-trivial syntax and must be parsed rather than shown raw for a polished UI.

4. Nominatim (address only)

Nominatim is OSM's geocoder. It is free and keyless, but it only resolves names to coordinates or coordinates to an address/place. It does not expose cuisine or opening hours and should not be used as a POI database.

  • Good for: geocoding /map <location> and reverse geocoding a point to a formatted address.
  • Usage policy: identify the app with a real User-Agent and contact, maximum ~1 request/second, cache results, no bulk scraping.
  • Already used by /map for geocoding.

5. Geoapify Places / Place Details (key, free tier)

Geoapify is a hosted location platform built primarily on OpenStreetMap plus Wikidata. It is the closest hosted replacement for the Yelp detail call if a free API key is acceptable.

ItemDetails
KeyRequired (free account, no credit card for the free plan).
Free plan3,000 credits/day, up to 5 requests/second.
Places cost1 credit per 20 returned places (e.g. 50 results = 3 credits).

AttributionOpenStreetMap required; "Powered by Geoapify" required on the free plan.

Example details lookup by OSM identity:

GET https://api.geoapify.com/v2/place-details
    ?osm_id=365489125&osm_type=n
    &apiKey=YOUR_KEY

Why not make it primary? It still requires a key and account, and the free plan has a daily credit ceiling. It is an excellent fallback when OSM tags are missing or when normalized categories/hours are worth the key management.

6. Overture Maps Places (open data)

Overture Places is a free, open, global POI dataset (88.4 million places in the October 2026 release). It is not a live point-query API: the data is distributed as GeoParquet on Amazon S3 and Azure Blob Storage, queried with DuckDB, Spark, or the Overture Python client.

  • License: CDLA Permissive 2.0 / Apache 2.0 depending on source; no ODbL share-alike for the Overture data itself.
  • Fields: names, basic_category and taxonomy, addresses, websites, phones, socials, emails, brand, confidence, operating_status, GERS id.
  • Missing: opening hours. operating_status means "open / temporarily closed / permanently closed", not opening hours.
  • Coverage: global, but the project documents duplicates, a high junk rate, and low property completeness; filter by confidence.
  • Use: download or pre-index a city/region and use it to fill missing names, categories, addresses, phones, and websites around an OSM restaurant. Keep OSM as the hours source.

7. Foursquare OS Places (open data)

Foursquare OS Places is a free, Apache-2.0 global POI dataset (20+ attributes and more than 1,000 categories). Like Overture, it is bulk data (Parquet/Iceberg, ~263 GB at one point), not a keyless REST detail endpoint.

  • Fields include name, address parts, locality/region/postcode, phone, website, email, social handles, and Foursquare category ids/labels.
  • The open schema does not include opening hours; hours, photos, and richer attributes are in the commercial Places Pro/Premium products.
  • Access now requires a free Places Portal account/access token, or approved HuggingFace access; attribution to Foursquare and the Apache NOTICE is required.
  • Best used as a local enrichment index for names, categories, and contact details, not as a keyless replacement for Yelp hours.

8. Yelp Fusion v3 (baseline / paid)

Yelp remains the strongest source for ratings, review counts, price level, photos, and Yelp-branded content. It is no longer a permanent free API:

  • 30-day trial: 5,000 API calls for evaluation only.
  • Paid plans (checked 2026): Base $229/month, Enhanced $299/month, Premium $643/month, each including 30,000 calls/month and a 5,000/day cap; overage billed per 1,000 calls.
  • The Base plan has no photos and no review excerpts; Enhanced/Premium add a few photos/excerpts.
  • Caching of Yelp content is limited to 24 hours; business IDs may be stored indefinitely.
  • Business Search + Business Details provide exactly the fields this feature uses (name, categories, address, phone, hours, rating, price), which is why the current implementation works well when a key is available.

Verdict: keep Yelp as an optional enrichment if ratings/reviews or Yelp-branded data are required, not as the only path for basic restaurant details.

9. No-key third-party wrappers and paid proxies

Several services wrap OSM/Overpass and expose a "no key" REST endpoint. They can be useful for prototypes, but they add a dependency, have no service-level guarantee, and often have unclear long-term funding or rate-limit policies.

ServiceModelNotes
BizData API Free, no key, OSM-backed 37 categories, returns name, address, phone, website, coordinates, opening hours. Advertises no key and no rate limit; no SLA. Useful for a quick prototype, not a critical dependency.
2s.io poi.near No key, pay-per-call (USDC) Overpass-backed, nearest-first POIs with cuisine, address, phone, website, opening hours. A free trial call exists, but it is not a free production service and requires a crypto wallet.
POS.DO Free tier, no key; paid fields Restaurant records in selected markets, core fields free, reviews and AI insights paid per call. Niche coverage; not a general worldwide replacement.
Commercial Overpass hosts Key / paid Geofabrik, Overspan, Tracestrack, etc. Useful if this grows into a production app that must not depend on volunteer servers.
Scraping warning: scraping Yelp or Google Maps pages may appear free, but it violates their terms, is fragile against markup and anti-bot changes, and creates legal/operational risk. It is not a recommended replacement.

10. Opening-hours parsing

OSM's opening_hours value is a specification, not a simple string. Examples range from 24/7 and Mo-Fr 11:00-22:00 to rules with holidays, seasonal ranges, sunset, and "off" overrides:

Mo-Fr 11:00-22:00; Sa 10:00-23:00; Su 10:00-21:00
Mo-Fr 12:00-18:00; We off; Sa,PH 12:00-17:00
Mo-Su 08:30-09:00 off; Tu-Su,PH 14:00-14:30 off

Recommended parsers for this project:

LibraryLanguageLicenseNotes
opening_hours_py Python (Rust bindings) MIT OR Apache-2.0 Fast, supports state, next change, normalization, timezone and holiday data. Best fit for a Python server.
opening_hours.js JavaScript LGPL-3.0 Reference implementation; can be run from Node if a JS service is preferred.
pyopening_hours Python wrapper AGPL-3.0 Wraps opening_hours.js; check the AGPL implications before shipping.
humanized_opening_hours Python AGPL-3.0 Human-readable descriptions; project development is paused.
KOpeningHours C++/Python bindings KDE license Very complete parser/validator; heavier dependency.

Minimum useful behavior for the UI: show the raw expression when parsing fails, compute open now and next change when parsing succeeds, and never invent hours for restaurants without an opening_hours tag.

11. Rate limits, caching, licensing

Overpass

  • The main overpass-api.de fair-use guideline is roughly 10,000 queries and 1 GB of downloads per day for occasional use; recurring apps should stay around 100 queries and 10 MB per day, and all users of an app count toward the total.
  • Commercial use should use a self-hosted or paid Overpass instance.
  • Send a meaningful User-Agent; avoid parallel query storms; on 429 pause at least 30 seconds and check /api/status; on 504 reduce [timeout:] / [maxsize:]. Overpass may not provide a useful Retry-After, so back off conservatively.
  • The public overpass-api.de instance is frequently overloaded. Alternatives with global coverage include overpass.openstreetmap.fr, overpass.private.coffee, and maps.mail.ru/osm/tools/overpass; read each instance's usage policy. The current /map code already tries the French instance first, then overpass-api.de, then kumi.systems.

Geoapify

  • Free plan: 3,000 credits/day, 5 requests/second.
  • Places: 1 credit per 20 returned places; Place Details: 1 credit for the details feature.
  • OSM attribution required; "Powered by Geoapify" on the free plan.
  • Results may be cached, stored, and redistributed with attribution.

Licensing

  • OSM: ODbL. Attribution "© OpenStreetMap contributors" is required. A derived database may need to be offered under ODbL; using the data internally or building an app on top needs attribution.
  • Overture: CDLA Permissive 2.0 / Apache 2.0 per source; attribution/licensing page applies.
  • Foursquare OS Places: Apache 2.0 plus the Foursquare NOTICE; preserve attribution.
  • Yelp: Yelp display requirements; content caching limited to 24 hours, business IDs may be stored indefinitely.

13. Recommended architecture for this project

  1. Primary detail call: use the OSM object already selected in the Nearby Restaurants list. Return osm_type and osm_id with the list payload, then fetch that exact object from Overpass when the modal opens. Keep the lat/lon radius query as a fallback if the OSM id is missing.
  2. Normalize tags into the UI model: name, type, cuisine list, address, hours, phone, website, service flags, dietary and accessibility tags.
  3. Parse hours with opening_hours_py; show "open now", "closes at …", and the next change when available; fall back to the raw expression if parsing fails.
  4. Cache per OSM id (for example 1–24 hours) and rate-limit Overpass calls. A restaurant's name/address/hours do not change every minute.
  5. Keep Yelp optional: if YELP_API_KEY is present, merge rating, review count, price, and photos into the same modal. If absent, the OSM section still works with no key.
  6. Optional enrichment later: index a city extract from Overture or Foursquare OS Places to fill missing names/categories/ addresses/phones, or use Geoapify if a free key is acceptable. Do not use either as the hours source.
  7. Attribution: display "© OpenStreetMap contributors" wherever the OSM detail data is shown; add the Yelp or Geoapify attribution when those sources are enabled.

14. Implementation sketch

Fetch one restaurant by its OSM identity:

import requests

OVERPASS_URL = "https://overpass.openstreetmap.fr/api/interpreter"

def fetch_osm_restaurant(osm_type: str, osm_id: int) -> dict:
    query = f"[out:json][timeout:15];\n{osm_type}({osm_id});\nout center;"
    response = requests.get(
        OVERPASS_URL,
        params={"data": query},
        headers={
            "User-Agent": "local-llm-chat/1.0 (+https://github.com/)",
            "Accept": "application/json",
        },
        timeout=(8, 30),
    )
    response.raise_for_status()
    elements = response.json().get("elements", [])
    return elements[0] if elements else {}

Normalize the tags:

def normalize_restaurant(element: dict) -> dict:
    tags = element.get("tags") or {}
    return {
        "name": tags.get("name", ""),
        "type": (tags.get("amenity") or "").replace("_", " ").title(),
        "cuisine": [
            value.strip()
            for value in (tags.get("cuisine") or "").split(";")
            if value.strip()
        ],
        "address": " ".join(
            value for value in (
                tags.get("addr:housenumber", ""),
                tags.get("addr:street", ""),
                tags.get("addr:city", ""),
                tags.get("addr:postcode", ""),
            ) if value
        ),
        "opening_hours": tags.get("opening_hours", ""),
        "phone": tags.get("phone") or tags.get("contact:phone", ""),
        "website": tags.get("website") or tags.get("contact:website", ""),
        "takeaway": tags.get("takeaway", ""),
        "delivery": tags.get("delivery", ""),
        "outdoor_seating": tags.get("outdoor_seating", ""),
        "wheelchair": tags.get("wheelchair", ""),
    }

Parse the hours (optional but recommended):

from opening_hours import OpeningHours

def summarize_hours(value: str, lat: float, lon: float) -> dict:
    if not value:
        return {"raw": "", "open_now": None, "next_change": None}
    try:
        hours = OpeningHours(value, coords=(lat, lon))
        return {
            "raw": value,
            "open_now": hours.state() == "open",
            "next_change": hours.next_change().isoformat(),
        }
    except Exception:
        return {"raw": value, "open_now": None, "next_change": None}

The exact opening_hours_py API can vary by version; check the installed package's documentation. The important design rule is to keep parsing failures non-fatal and show the raw expression.
